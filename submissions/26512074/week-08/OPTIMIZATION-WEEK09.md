# Round 3 운영 최적화 — 2026-11-04

브랜치 `week-09`, 작업 디렉터리 `submissions/26512074/week-08`. 원격 `week-09-credit-efficient`의 네 파일 변경을 검토하고 결정론적 가격 계산 도우미를 가져왔다. 모델 선택 분기는 유지하지 않고 실측 가격 정책으로 대체했다. 기존 미커밋 로그와 루트 AGENTS.md는 보존했다.

## P0: 호출 비용

기존 11월 4일 operator 로그에서 `seller_open` 275회, `seller_turn` 263회, 의미 해석 8회를 확인했다. 누적 호출 수이며 시간당 수치가 아니다. 해당 로그에는 사용 토큰이 없어 토큰·금액 절감률을 계산하지 않았다.

새 판매 호가·역제안·수락은 Python으로 실행한다. 판매자가 모호한 문장을 받으면 숫자로 다시 제안하도록 응답한다. 구매·게시판 견적 해석도 기본 모델 비활성화다. 의미 해석을 명시적으로 활성화한 경우에만 기존 시간당 6개 허가 및 타임아웃을 사용한다. 원래 서명 및 결제 경로는 변경하지 않았다. 모델 실행 시 `model-usage.jsonl`에 시작 횟수와 확인 가능한 사용량을 기록한다.

## P1: 가격, 협상, 재고

- 가격 후보: 원가 대비 5/10/15/25/35/50/65%. 관측된 SKU 판매 10건 이상이고 재고 2개 이하일 때만 80% 후보를 추가한다. 상품 정가가 상한이다.
- 탐색: 기본 12%, 허용 10~15%. 나머지는 충분한 표본에서 SKU·등급별 체결 이익과 협상 시간으로 계산한 보상률이 가장 높은 가격을 사용한다. 표본이 적으면 15% 사전 정책을 유지한다. 무작위 탐색 결과를 보장된 개선으로 간주하지 않는다.
- 서명 영수증 발행은 판매 실적이 아니다. 공개 정산 원장의 단위 ID와 실제 금액이 일치해야 성공·마진으로 기록한다. 300초가 지난 시도만 가격 비교에 사용한다.
- 협상: 즉시 수락 이익과 역제안 확률·마진·지연 비용을 비교한다. 표본 12건 미만이면 기존 안정적 수락을 유지한다. 가격 민감형·빠른 수락형·보증 요청형·다회 협상을 구분한다. 익명 A2A의 다회 협상을 동일 구매자의 반복 방문으로 주장하지 않는다. 비공개 예산을 사용하지 않는다.
- 매입: 보수적인 최대 매입가로 예산을 확보하되, 실제 관측 매입비와 판매가로 예상 자본 효율을 평가한다. 낮은 판매율, 예상 폐기, 보관비, 기존 재고를 반영한다. 교체 매입비·판매 대기 시간은 추정값이다.
- 현금 2,000,000, 재고 1,500,000, 회당 매입 250,000 한도를 설정 파일로 옮겼으며 자동 상향하지 않는다. 식품 할인 및 보증 충당금 검사를 보존했다.

## P2: 6시간 워커

`optimizer.py`는 별도 프로세스이며 모델을 사용하지 않는다. 매번 공개 ALL을 기준으로 상위 다섯 곳을 다시 선정한다. 공개 잔고 손익·매출·거래·평판, 공개 재고, 원장에서 확인한 SKU별 가격을 수집하고 이전 스냅샷과 차이를 계산한다. 경쟁 원가·마진·내부 정책은 알 수 없으며 카드 설명은 검증되지 않은 주장으로 저장한다.

6시간·24시간·7일 통계를 저장한다. 6시간 이상 비교 구간, 시도 30회·정산 10회 이상, 충분한 실제 원가가 있어야 강화를 검토한다. 가격별 실험 성과가 입증되면 탐색률과 재고 배수만 소폭 바꾼다. 한 번에 최대 두 변수를 수정한다. Profit 속도, 성립률, 평점, 환불률이 악화되면 마지막 정상 설정으로 복구한다. 외부 수요 변화와 정책 효과를 인과적으로 구별했다고 주장하지 않는다.

OS 파일 잠금으로 중복 워커를 막고, 원자적 파일 교체·미완료 정책 적용 저널로 재시작을 복구한다. API 실패 시 기존 설정을 유지한다. 단순 시간 경과만으로 정책을 바꾸지 않는다.

저장 위치는 비공개 `.market/optimization/`이다:

- `performance-<timestamp>.json`, `review-<timestamp>.md`
- `policy-history.jsonl`, `model-usage.jsonl`
- `latest.json`, `state.json`, `rollout-verification.json`
- `.market/optimization.sqlite3`: 가격 시도, 실제 정산, 원가와 비용

첫 실제 실행은 비교 기간 부족으로 정책을 유지했다. 상위 다섯 곳은 dragonash, inextro, yms979, dae-yangkim, nocha12였다. 이후 주기마다 다시 선정한다.

## P3: 구매·게시판

기존 구매 시도와 인증서·예산·영수증 검사를 보존했다. 과거 실제 구매가격과 결제 성공률을 이용해 기대 Surplus로 상점 순서를 정한다. 미확인 견적에는 기존 보수적 가격 상한을 사용한다. 상점별 최근 호가·제안 기록도 보존한다.

게시판의 기존 반응·전후 거래·주제별 보상 집계를 유지하고 6시간 스냅샷에 포함한다. 게시 주기는 허용 범위의 설정으로 읽는다. 게시 전후 변화는 인과 효과로 주장하지 않는다. 추가 비교 표본이 없으면 게시 전략을 자동 변경하지 않는다.

## P4: 적용과 한계

기존 키의 SHA-256 지문이 동일함을 확인했다. 운영 키, 등록 ID, 결제 프록시, 터널을 교체하지 않았다. 키트 watchdog으로 판매자만 1.4.0으로 교체했고 공개 카드와 Online을 확인했다. 이 교체는 인메모리 미완료 협상 상태를 이관하지 않는다. 결제 프록시의 이미 발행된 영수증·세션은 보존되지만 전환 중 미완료 협상 무손실은 보장하지 않는다.
