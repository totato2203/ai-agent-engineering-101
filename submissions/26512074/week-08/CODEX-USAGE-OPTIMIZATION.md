# Round 3: Codex 사용량 절감 변경

이 변경은 `week-09`에서 분기한 별도 브랜치의 비파괴적 수정이다. 자동 시장 운영 중인 PC의 로컬 프로세스에는 아직 적용되지 않았다.

- 일반적인 판매 호가/역제안에서 매 메시지마다 수행되던 `codex exec` 호출을 Python 규칙(`pricing_fastpath.py`)으로 대체했다.
- 판매자의 기존 잔여 원가 하한 검사, 유효한 제안 즉시 수락, 서명 영수증과 ACP 결제 코드에는 손대지 않았다.
- 모델을 다시 써야 할 경우 운영 환경변수 `ROUND3_LLM_NEGOTIATION=1`을 설정하면 된다. 기본은 `0`이다.
- `buyer_r3.py`는 기존대로 유지했다. 난해한 가격 텍스트에 대해서는 `policy.py`의 의미 해석 모델 호출(기존 시간당 최대 6회)이 발생할 수 있다.
- 시장 시세·게시판 분석 워커는 대부분 Python 규칙을 실행하며, 모델 호출 자체가 아닌 시장 API와 A2A 견적 조회가 반복된다. 이번 수정에서 워커 기능과 게시 간격을 바꾸지 않았다.
- 새 로직의 기본 가격 경로 3개 단위 테스트는 로컬 Python 환경에서 모두 통과. 전체 라이브 ACP 거래 테스트와 서버 재배포는 미실시.

## 적용

로컬 저장소의 미커밋 변경사항을 먼저 보호하고, 다음 중 적절한 방식으로 작업 파일만 합친다.

```powershell
cd C:\AX\ai-agent-engineering-101
git fetch origin week-09-credit-efficient
git status --short
# 로컬 week-09 작업이 보존된 상태에서 필요한 변경만 선택하거나 검토:
git diff week-09..origin/week-09-credit-efficient -- submissions/26512074/week-08/seller_r3.py
```

시장 가동 중에는 프로세스를 무작정 중단하지 말고 공식 키트의 자식 seller 재시작 절차를 이용한다. 로컬 운영 중인 seller에는 새 코드를 다시 읽히기 전까지 효과가 없다.

## 측정

변경 전후 `harness_start` 이벤트에서 `seller_open`/`seller_turn` 수를 비교한다. 정상 숫자 제안 경로의 호출 수가 0이면 이번 절감 목표를 충족한다. 전체 거래 성립률·수익률도 같이 비교해 가격 정책으로 인한 성능 저하를 확인한다.

웹사이트를 브라우저에서 열어 놓는 것 자체는 Codex CLI 모델 호출을 발생시키지 않는다. 시장에 등록된 로컬 buyer/seller는 주문을 받으면 백그라운드에서 처리하므로 화면을 닫아도 계속 실행될 수 있다.
